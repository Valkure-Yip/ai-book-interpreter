# v0.1 MVP Execution Plan

> 状态：**active**
> 目标：6 周内做出能跑通"英→中、EPUB/TXT → Markdown、含术语锁与滑动窗口"的最小可用版本。
> 范围之外的特性进 v0.2+。
>
> 选型决策详见 [`../../design-docs/tech-stack.md`](../../design-docs/tech-stack.md)。

## 目标准则

- **能用**：一本中等大小（10 万字）的英文学术书 EPUB / TXT → 中文 Markdown，单命令完成
- **可控**：成本 hard cap、checkpoint 续跑、flagged 段落可见
- **可观测**：每次 LLM 调用在 Langfuse 中可追溯（prompt、token、cost、latency、retry 链路）
- **可读**：所有产物（IR、survey、translations、report）都是版本化、人类可读
- **可扩展**：分层架构定型；后续加 pdf、其他 OpenAI-compatible provider 只需新增配置而非新增代码

## 范围（IN / OUT）

### IN（v0.1 必做）

- 输入：**EPUB + TXT**
- 输出：`translated.md` + `bilingual.md` + `report.md` + `glossary.json`
- 语言对：**en → zh**
- LLM 接入：**OpenAI-compatible API**（统一一个客户端，通过 `base_url` 切换 OpenAI / DeepSeek / Together / vLLM / Ollama OpenAI 兼容端点 / 任意自建网关）
- 编排框架：**LangChain**（prompt 模板、结构化输出、链路、重试）
- 观测：**Langfuse**（trace、prompt 版本、cost、dataset）+ 本地 `events.jsonl`（项目级业务事件）
- 三遍流水线（Pass 0/1/2/3）全部贯通
- 段落级 checkpoint + `abi resume`
- 全部不变量的 linter（D1-D13、D17）
- 段落级质量分数 + `report.md`

### OUT（推迟到 v0.2+）

- PDF 输入（含 OCR fallback）
- 其他语言对
- **非** OpenAI-compatible 的原生协议（如 Anthropic Messages API 原生形态——可走兼容代理）
- `annotated` 模式（mindmap、章节摘要嵌入）
- 自评审（`--quality high` 的 Reviewer）
- 编辑后增量重跑（`abi glossary edit`）
- 多书批处理

### 技术栈说明

**为什么 LangChain**：
- `ChatPromptTemplate` + `PydanticOutputParser` 直接给我们"prompt 模板 + 结构化输出 + schema 校验"一条龙
- LCEL（`|` 运算符）让 "prompt → llm → parser → 重试" 的链路成为一等表达式
- `with_structured_output(schema)` 直接对接 OpenAI 函数调用 / JSON mode
- Langfuse 通过 LangChain CallbackHandler 自动接管，**零侵入**追踪

**为什么 OpenAI-compatible 统一接入**：
- 单一 `ChatOpenAI` 类即可对接 OpenAI / DeepSeek / Together / Moonshot / SiliconFlow / Ollama / vLLM / LiteLLM 网关
- 切换 provider = 改环境变量与配置，**不改代码**
- 真正"非兼容"的（如 Anthropic 原生 API）也可通过 LiteLLM 代理转换为兼容形式（v0.2 再启用）

**为什么 Langfuse**：
- 自托管 / 云端均可选，开源
- 与 LangChain 一行接入，无需埋点改写
- Prompt 版本、dataset、人工评分、cost 报表全有
- 与本项目 `events.jsonl` 互补：Langfuse 管 LLM 链路；本地事件管段落/章节/glossary 业务事件

## 验收用例

```bash
# 用例 1：OpenAI 官方 + EPUB
export LLM_API_KEY=$OPENAI_API_KEY
export LLM_BASE_URL=https://api.openai.com/v1
abi translate ./fixture-1.epub -o ./out-1 --mode translated,bilingual --model gpt-4o-mini

# 用例 2：DeepSeek 兼容端点 + TXT
export LLM_API_KEY=$DEEPSEEK_API_KEY
export LLM_BASE_URL=https://api.deepseek.com/v1
abi translate ./fixture-2.txt -o ./out-2 --mode translated,bilingual --model deepseek-chat --max-cost-usd 5

# 用例 3：续跑
^C   # 中断
abi resume
```

验收标准：
- 三 pass 全部完成，无未捕获异常
- `out-*/translated.md` 可被 markdown-it 解析无错
- `out-*/report.md` 显示 flagged 段比例 < 5%
- 关键术语在 glossary.json 中且整本书严格遵循
- 成本不超过 `--max-cost-usd`
- Langfuse 中可见两次 run 的完整 trace 树，能按 `book_id` 检索
- 中断后 `abi resume` 能从上次位置续跑，且 Langfuse 上能看到续跑只产生增量 traces

## 风险与已知问题

| 风险 | 缓解 |
|---|---|
| 第三方 OpenAI 兼容端点行为偏差（如不支持 `response_format=json_schema`） | `providers/llm/structured.py` 内置两套策略：json_schema → tool calling → 最后 JSON mode + 后处理解析；探测启动时一次 |
| LangChain 升级破坏 | pin 到具体 minor version；用 LCEL 而非 legacy chains，向前兼容性更好 |
| Langfuse 不可达时阻塞 | CallbackHandler 默认异步 + 失败静默；本地 `events.jsonl` 始终落盘作为 fallback |
| Langfuse 写入泄漏内容 | 通过配置开关：默认仅记录 metadata + token，不上传 prompt/completion 全文；用户显式开启 `LANGFUSE_FULL_PAYLOAD=1` 才传 |
| LLM 不稳定导致重试爆量 | `with_retry(stop_after_attempt=3)` + `max_revision_rounds=2` + cost cap 兜底 |
| TXT 章节误识别 | fixture 包含"无显式章节"案例；落 warning 但不阻塞 |
| 滑动窗口 token 超限 | 预算 gate + trim_order |

## 不变量加固（v0.1 落地）

- D2 白名单更新：`langchain*`、`langfuse*` 只能在 `src/providers/**` 中 import
- 新增 lint：`tools/lint/no_direct_chat_model.py` — 业务层不得直接构造 `ChatOpenAI`，必须经 `providers.llm.get_chat_model()`
- 新增 lint：`tools/lint/langfuse_payload.py` — 任何把段落正文塞进 Langfuse metadata 的代码路径，需显式注解 `# allow-payload: <reason>`
