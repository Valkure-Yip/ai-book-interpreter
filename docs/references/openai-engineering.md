# OpenAI Engineering：在智能体优先的世界中利用 Codex

> 来源：https://openai.com/zh-Hans-CN/index/harness-engineering/
> 上次同步：2026-02-11
> 摘要由人类整理，关键引文与原文链接保留。

## 一句话观点

> "人类掌舵。智能体执行。" — 工程师的主要工作从"编写代码"变成"设计环境、明确意图、构建反馈回路"。

## 与本项目相关的核心原则

### 1. 代码仓库即记录系统
所有设计决策、产品规范、运行结果都以**可被智能体直接消费**的形式入库。Slack / 脑中的知识等于不存在。

→ 本项目落地：`docs/`、`runs/`、`AGENTS.md`、版本化工件流

### 2. 渐进式披露 / 短 AGENTS.md
"地图，不是百科全书"。100 行左右，指向更深的真实信息源。

→ 本项目落地：`AGENTS.md ~120 行`

### 3. 严格分层 + 机械执行
固定层 + 单向依赖 + 自定义 linter。

→ 本项目落地：`ARCHITECTURE.md §2`、`tools/lint/layered_imports.py`

### 4. 边界处解析数据形状（Parse, don't validate）
所有外部输入在进入业务层前被解析为强类型。

→ 本项目落地：`DESIGN.md §D4`，所有 LLM 输出、文件输入、CLI 参数均用 pydantic

### 5. 品味即不变式
"在以人为本的工作流程中，这些规则可能会让人感到迂腐或束缚。有了智能体，它们就成了倍增器：一旦编码，它们就能立即应用于所有地方。"

→ 本项目落地：`DESIGN.md` 全部 D 规则、`QUALITY_SCORE.md` 评分公式、glossary lint

### 6. 智能体可读性优先
"从智能体的角度来看，它在运行时无法在情境中访问的任何内容都是不存在的。"

→ 本项目落地：`events.jsonl`、`metrics.json`、`docs/generated/` 全部对智能体可读

### 7. 垃圾回收
定期清理"AI 残渣"——技术债像高息贷款，每天还小钱比一次性还痛苦债轻松。

→ 本项目落地：`tools/garden/` 计划（v0.2+），周扫漂移并发 PR

### 8. 吞吐量改变合并理念
"在低吞吐量环境中，这样做是不负责任的。而在这里，这通常是正确的选择。" — 短 PR、CI 不阻塞、纠错成本低于等待成本。

→ 本项目落地：PR 准则（README/CONTRIBUTING，TBD）

## 与本项目的差异

OpenAI 团队描述的是**完全由智能体生成的代码库**；本项目目前以"人 + 智能体协作"为现实定位。但所有约束与工具都按"智能体也能维护"来设计，为未来过渡留余地。
